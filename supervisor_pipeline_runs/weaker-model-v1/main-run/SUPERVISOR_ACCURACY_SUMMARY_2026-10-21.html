How the accuracy drops / 准确率如何下降

EN
  • One error pattern. In all 147 misranked runs, gpt-5.5 ranked the entry-point (facade) method first, that is, the existing method the failing test calls. In almost all of them it had already displayed and read the faulty method.
  • What it goes with (pattern seen after batch 2, then checked on new instances). Shifts concentrate where the injected omission leaves no visible trace inside the faulty method, for example a parameter that cannot change the result, a dead local or decision, a visibly incomplete set of cases, or a contradiction with its own documentation. We froze this as a construction rule before building batches 3 and 4. The pre-registered readings were met: batch 3 shifted on 15 of 17 instances (SUPPORTED), and batch 4 on 11 of 12 (REPLICATES).
中文
  • 单一错误模式。在全部 147 次排错的运行中，gpt-5.5 都把入口（facade）方法排在第一，也就是失败测试调用的那个已有方法。几乎所有这些运行里，它其实已经显示并读过故障方法。
  • 相关规律（第 2 批后观察到，随后在新实例上检验）。shift 集中出现在注入的遗漏没有在故障方法内部留下可见痕迹的情况，可见痕迹例如：不会影响结果的参数、无用的局部变量或判断、明显不完整的分支集合，或与自身文档的矛盾。我们在构造第 3、4 批之前把这一点冻结为构造规则。预注册的判定都达到了：第 3 批 17 个实例中 15 个 shift（SUPPORTED），第 4 批 12 个中 11 个（REPLICATES）。

Important caveats / 重要说明

EN
  1. Different instance sets. The 100% figures come from other instance sets, not from these same 47 bugs without the transformation. As instructed, the main run has no baseline arm, so it cannot show how much of the drop on these bugs the construction causes, or which part of it: the hop chain, the misleading facade comment, or the omission type. The only same-bug comparison is Stage B (3 bugs): the single-hop control C00 scored 15/15, against 3/15 for C10.
  2. Consistency checks, not causal tests. The batch-3 and batch-4 readings are consistency checks of a hypothesis, made without a control arm.
  3. Constructed instances. The instances are real Defects4J bug identities with a synthetic injected fault, not the original Defects4J bugs.
中文
  1. 实例集不同。100% 来自其他实例集，而不是这 47 个 bug 未经变换时的结果。按要求，主实验没有设置基线组，所以无法说明这些 bug 上的下降有多少由构造造成，或由构造中的哪一部分造成：调用链、误导性的 facade 注释，还是遗漏类型。唯一的同一 bug 对比来自 Stage B（3 个 bug）：单跳对照 C00 为 15/15，C10 为 3/15。
  2. 一致性检验，而非因果检验。第 3、4 批的判定是对一个假设的一致性检验，并没有对照组。
  3. 构造的实例。实例使用真实的 Defects4J bug 身份，但故障是人工注入的，并不是 Defects4J 原有的 bug。

Cost and next steps / 成本与下一步

EN
  • Cost. Total spend is $159.58 recorded, $163.95 including estimates, within the $200 ceiling.
  • Candidate pool. The pool of eligible bugs is used up. Of the 23 left, 9 could only reuse a facade method already in use, and 14 have only targets that already failed to build in a sibling bug.
  • Decisions needed.
    1. Whether to widen the pool, for example to the projects excluded for slow test suites.
    2. Whether to add a baseline arm, so the drop can be attributed to a component.
    3. Whether to run GPT-5.6.
中文
  • 成本。总花费为 $159.58（已记录），含估算为 $163.95，在 $200 上限之内。
  • 候选池。符合条件的 bug 池已经用完。剩下的 23 个中，9 个只能复用已用过的 facade 方法，14 个的目标方法已在共享该方法的其他 bug 中构造失败。
  • 需要决定。
    1. 是否扩大候选池，例如纳入因测试太慢而排除的项目。
    2. 是否加入基线组，以确定准确率下降由哪个部分造成。
    3. 是否运行 GPT-5.6。
